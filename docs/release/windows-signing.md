# Windows Codex Preview Signing

The Codex preview separates build, signing, and installation checks. `build-codex-release.ps1` produces an unsigned MSI/EXE plus `manifest.json`, `sbom.json`, and `provenance.json`. The manifest binds the artifact SHA-256 to the package version, channel, schema compatibility, SBOM, and provenance.

## Build

```powershell
powershell -ExecutionPolicy Bypass -File scripts/build-codex-release.ps1 -Channel preview
```

For a controlled fixture, pass `-ArtifactPath` and `-SkipBuild`. An unsigned manifest is intentionally not installable.

## Sign

Signing runs on a Windows signing host with the certificate in the machine or user certificate store. Pass only the certificate thumbprint; never pass a PFX path, password, private key, or secret through the command line.

```powershell
powershell -ExecutionPolicy Bypass -File scripts/sign-release.ps1 `
  -ArtifactPath artifacts\codex-release\preview\0.1.0\AgentMissionControl-0.1.0-preview.msi `
  -ManifestPath artifacts\codex-release\preview\0.1.0\manifest.json `
  -CertificateThumbprint $env:MISSION_CONTROL_SIGNING_THUMBPRINT
```

The script uses `signtool` Authenticode signing and verification, then binds the final post-signing artifact hash and the CI-provided updater signature into the manifest. Logs contain no private key or password.

The script then obtains the Tauri updater signature for that final artifact. CI may provide the detached signature as `TAURI_UPDATER_SIGNATURE`, or provide `TAURI_SIGNING_PRIVATE_KEY` (and, when required, `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`) so the workspace Tauri signer can create `<artifact>.sig`. These values must come from the CI secret store and are never command-line arguments or log output. The script refuses to derive a signature from a hash. Authenticode and the Tauri updater signature are separate checks, and the Rust guard only accepts the `tauri-updater-v1` scheme after Tauri reports the asymmetric signature as verified.

## Update and rollback gates

`apps/desktop/src-tauri/src/update_guard.rs` rejects unsigned or untrusted manifests, hash mismatches, channel changes, non-monotonic versions, incompatible schemas, and updates while a Mission is active. A backup must exist before installation. Production callers use `validate_verified` only after Tauri updater verification; the deterministic `fixture-sha256-v1` scheme is compiled for tests and cannot pass the production constructor. `test-update-rollback.ps1` exercises the same release invariants with a disposable old/new install and verifies that an interrupted update restores a bootable binary without changing the committed data file.

The updater remains disabled in the current Tauri config until a signed endpoint and public key are supplied by CI. A clean Windows VM must still verify install, upgrade, interruption, and rollback before enabling the endpoint.

## Round 6 readiness and GitHub secrets

The mechanical self-check is `scripts/test-signing-chain.ps1`. It copies an existing
release artifact into an isolated gate run, creates a certificate whose subject is
`Agent Mission Control TEST self-signed`, runs `sign-release.ps1` and Authenticode
verification when `signtool.exe` is installed, then compares the artifact SHA-256 in
`manifest.json`, `provenance.json`, and `sbom.json`. Its report always contains
`certificateType=TEST-self-signed`, `productionSigningStatus=deferred-ci`, and
`releaseReady=false`; it is never production signing evidence.

The production workflow may be enabled only after these GitHub Actions secrets are
configured from the organization's code-signing vault:

| Secret | Format | Acquisition / use |
| --- | --- | --- |
| `MISSION_CONTROL_SIGNING_PFX_BASE64` | Base64-encoded password-protected PFX | Export the approved Authenticode certificate as PFX and base64-encode the file without committing it. |
| `MISSION_CONTROL_SIGNING_PFX_PASSWORD` | Plain secret value | Password supplied by the certificate authority/vault when exporting the PFX. |
| `MISSION_CONTROL_SIGNING_THUMBPRINT` | 40-character SHA-1 thumbprint | Read from the approved certificate store entry; compare with `Get-AuthenticodeSignature`. |
| `TAURI_SIGNING_PRIVATE_KEY` | Tauri updater private key text | Retrieve from the updater signing vault, or use the equivalent `TAURI_UPDATER_SIGNATURE` secret generated by the approved release process. |

Until all required values exist in CI and a release run verifies `Status=Valid` with
the expected thumbprint, the only truthful value is `signingStatus=deferred-ci`.
