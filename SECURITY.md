# Security Policy

## Reporting a vulnerability

Please do not open a public issue for a suspected vulnerability or include
secrets, private evidence, or exploit details in a discussion.

Before the first public release, the repository owner must enable GitHub
Private Vulnerability Reporting under **Settings -> Security -> Code security
and analysis**. Report vulnerabilities privately through the repository's
**Security -> Advisories -> Report a vulnerability** form. Until that channel
is enabled, contact the repository owner privately and share only the minimum
information needed to establish a secure reporting channel.

Include the affected version or commit, impact, reproduction steps, and any
suggested mitigation. You should receive an acknowledgement within seven days.

## Supported versions

Before a stable release, only the latest commit on the default branch receives
security fixes. Published support windows will be documented here when
versioned releases begin.
